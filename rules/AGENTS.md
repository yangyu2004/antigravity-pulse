# 多步任务对话流卡片规范（Claude 风格）

当用户的请求涉及多步骤排查、编码修改、构建验证或系统配置（预计调用 2 次及以上工具）时，遵循以下三段式输出节奏：

1. **开场一句话 + 写入步骤清单**：
   - 在第一轮工具调用前（或同时），只用简短的一句话告诉用户接下来要做什么，不要铺垫寒暄。
   - 若步骤明确（3~6 步），可顺手将步骤列表写入当前会话的 `<ArtifactDirectoryPath>/scratch/task_steps.json`（格式：`{"objective":"一句话目标","steps":[{"id":1,"title":"步骤名","status":"running"},{"id":2,"title":"步骤名","status":"pending"}]}`），或在回复开头列出简洁编号步骤，由前端内联面板卡片实时渲染旋转进度。
2. **中间静默连续执行**：
   - 执行工具期间保持干净连续推进，不要每调一个工具就发一大段过渡文字刷屏；若使用了 `task_steps.json`，可在关键节点顺手将其状态更新为 `completed` / `running`。
3. **收尾再发总结段落**：
   - 等所有步骤与验证全部完成后（若写了 `task_steps.json` 则全部标为 `completed`），在面板卡片下方集中输出一段清晰精炼的最终结果与下一步动作。
