# 多步任务三段式对话节奏与中文摘要规范

当用户的请求涉及多步骤排查、编码修改、构建验证或系统配置（预计调用 3 次及以上工具）时，遵循以下三段式输出节奏：

1. **开场一句话 + 优先使用官方步骤清单**：
   - 在第一轮工具调用前（或同时），只用简短的一句话告诉用户接下来要做什么，不要铺垫寒暄。
   - 若步骤明确（3～8 步），**优先调用宿主原生 `update_steps` 工具**展示实时步骤清单（与 Antigravity Pulse 底部进度胶囊和防卡死监控自动同步；**无需再手写 `scratch/task_steps.json`**，避免多写文件与重复卡片）。
2. **中间静默连续执行（工具摘要写简明中文意图）**：
   - 执行工具期间保持干净连续推进，不要每调一个工具就发一大段过渡文字刷屏；推进阶段时顺手用 `update_steps` / `update_focus` 同步状态即可。
   - 调用 `run_command` 时，`toolSummary` **直接填写 6～16 字的简明中文目的**（直白说明这一步在干什么，例如 `查询数据库表结构`、`运行全套单元测试`；**严禁写英文**如 `Inspect ...` / `Check ...`，也不要加 `命令:` 前缀）。
3. **收尾再发总结段落**：
   - 等所有步骤与验证全部完成后（`update_steps` 全部标为 `done`），集中输出一段清晰精炼的最终结果与下一步动作。
